## 1. 論文在做什麼

**作者:** Hesam Rashidi、Matthew Roorda(多倫多大學土木與礦業工程系)、Mehdi Nourinejad(約克大學土木工程系,通訊作者)。

**問題:** 傳統旅行推銷員問題(TSP)求出的最短路線在現場常常不實用,司機會偏離。原因有兩個:
- 演算法為了可解,做了簡化假設,例如行駛時間固定。
- 演算法沒有考慮收件人在不在家、哪裡好停車這類現場因素。

經驗司機會用自己累積的知識排出更實際的路線。論文想把這些知識從歷史路線中學出來。

### 1.1 資料:Amazon 最後一哩路線挑戰賽(2021)

| 項目 | 內容(論文第 3 節、表 1) |
|---|---|
| 規模 | 6,112 條實際路線,美國 5 城市(Austin、Boston、Chicago、Los Angeles、Seattle) |
| 每條路線的規模 | 平均約 140–154 個停靠點、約 240 件包裹、純行駛 3.3–3.8 小時 |
| 品質標籤 | Amazon 物流規劃人員依生產力、司機經驗、顧客滿意度,把每條路線標成高、中、低 |
| 標籤分布 | 高品質約 44.5%;低品質不到 2%,太少,所以作者把中、低合併,改成二元分類 |
| 時間窗 | 不到 8% 的包裹有指定時間窗 |
| 切分 | 85% 訓練、15% 測試,依品質、城市、是否投遞成功分層抽樣;再做 5 折交叉驗證 |

### 1.2 方法:兩個階段

**離線階段:學出「好路線」的特徵。** 作者設計了 250 多個特徵,主要分兩類:

| 類型 | 特徵 | 說明 |
|---|---|---|
| 實例特徵(不隨順序改變) | 停靠數、包裹數、涵蓋的區塊數、服務時間、出車時間、車輛容積、平日或假日、城市 | 描述這趟任務本身 |
| 路線特徵(隨順序改變) | 純行駛時間 | 不含服務時間 |
| | **回頭路距離** | 用 Uber 的 H3 六角形網格把服務區切成區塊;離開某區塊後又回來,就計入回頭路距離 |
| | **彎折能量** | 路線各轉角角度的總和;越多急轉、之字形,值越大 |
| | **到訪時段品質** | 某區塊在某時段被到訪時,過去有多少比例是高品質路線 × 投遞成功率;樣本少的再打折 |
| | 早到、遲到分鐘數 | 相對時間窗 |

比較 4 種分類器(期刊版表 3,交叉驗證平均):

| 模型 | 準確率 | AUC |
|---|---|---|
| **邏輯斯迴歸(LR,採用)** | 0.704 | 0.758 |
| 隨機森林 | 0.691 | 0.749 |
| 多層感知器 | 0.700 | 0.757 |
| 圖神經網路 GNN-wm | 0.688 | 0.747 |

四種模型差不多。選 LR 的原因有三:除了精確率以外各項最好、能看出各特徵是否顯著、運算快。GNN 稍差,作者推測是資料量不夠。

**邏輯斯迴歸的發現(表 4,係數為標準化值):**
- 停靠數越多(+0.489)、包裹越多(+0.093),越可能是高品質。作者認為這反映生產力。
- 回頭路越多(−0.423、−0.205)、彎折越多(−0.412)、行駛時間越長(−0.200),品質越低。
- **行駛時間不是影響最大的因素。** 置換重要性分析(附錄 B)中,前三名是彎折能量、回頭路、到訪時段品質。

**線上階段:資料導向插入法(DIIH)。**
1. 從「物流中心 → 物流中心」開始,每次隨機挑一個還沒排進去的停靠點。
2. 把它插到成本最低的位置。插入成本 = 行駛時間增量 + 回頭路 + 彎折能量增量 + 到訪時段品質變化,各項權重取自邏輯斯迴歸的係數。
   - 回頭路的處理方式:事先把跨區塊的行駛時間加上一個大懲罰值。
3. 在 1 秒內重複產生一批路線,再用分類器挑出最可能是高品質的一條。

### 1.3 主要結果(期刊版第 6 節)

| 指標 | 結果 |
|---|---|
| 分類器直接判定 | DIIH 的路線有 98.8% 被判為高品質 |
| 依分類器精確率 0.691、NPV 0.712 校正後 | DIIH **68.6%** 為高品質。比司機實際路線多 24.1%、比只看行駛時間的最佳解多 28.3%、比競賽冠軍 Cook et al. (2022) 多 22.4% |
| 校正方法的檢驗 | 司機實際路線校正後為 43.9%,與 Amazon 標記的 44.5% 接近 |
| **代價:行駛時間變長** | DIIH 的行駛時間中位數比近似最佳解(OR-Tools 引導局部搜尋,1 秒)多 **20.6%**,比司機實際路線多 13.9% |
| **司機實際路線 vs 最佳解** | 司機實際路線的行駛時間中位數比近似最佳解多 **5.9%**(第 7 節) |
| Amazon 官方相似度評分(越接近 0 越像高品質司機路線) | DIIH 0.119;只看行駛時間的最佳解 0.091;競賽冠軍 0.019。**DIIH 最差**,作者主張這個評分不能代表路線在現場的品質 |

### 1.4 限制(作者自述與我們的判斷)

- **「68.6% 高品質」不是實地驗證。** 這是用分類器自己判定、再用分類器的精確率校正得到的,分類器本身準確率只有約 0.70。作者也承認分類器是整個方法的瓶頸。
- **品質提升的代價是多跑。** 行駛時間多 13.9–20.6%,但論文沒有討論油耗或排放。
- **到訪時段品質假設兩個機率獨立。** 也就是「該時段常出現在高品質路線」與「該時段投遞成功率」被當成互不相關,作者自己列為未來要改進的地方。
- **程式與衍生資料沒有公開。** 原文寫的是「Data will be made available on request」。
- **單車 TSP,沒有容量限制。** 和我們的多車、有容量、跨品牌合併問題不同。

### 為什麼不建議下載

1. **情境差很多:** 美國電商包裹廂型車,一條路線約 150 個住家停靠點、240 件包裹;我們是臺灣超商冷鏈,一趟約 20 家門市。
2. **沒有我們最缺的東西:** 沒有油耗或排放、沒有冷藏、沒有跨品牌。
3. **它的貨量資料不能套用:** 包裹體積與車輛容積是電商包裹,不能推估超商的籠車數或裝載率。
4. **我們需要的數字,論文已經算好:** 「實際路線比最佳解長多少」論文已給出 5.9%。若要臺灣的版本,可以直接用全家實際趟次與 OSRM 距離計算(`poc/2_a_group_rebuild.ipynb` 已有 96 家全家門市的距離矩陣),更有說服力。

如果之後還是需要,可以只下載 `route_data.json`(79 MB)與 `actual_sequences.json`(9.7 MB)。

## 4. 建議怎麼寫進報告

**方法依據**(放在校準版原則 2「幹線順序固定」後面):

> 文獻指出,以最短行駛時間求得的配送路線在實務上常不可行,司機會依經驗偏離(Merchán et al., 2022;Rashidi et al., 2025)。Amazon 2021 年 6,112 條路線的資料顯示,司機實際路線的行駛時間中位數比近似最佳解多 5.9%(Rashidi et al., 2025)。因此本研究以全家實際路線的停靠順序為基準,以插入法(Campbell & Savelsbergh, 2004)加入共配門市,不重新最佳化整條路線。

**限制**(放在結果判讀或限制段):

> 本研究 B 組路線為模型求得,實際執行可能比模型多跑;美國資料顯示實際路線約比最佳解長 6%(Rashidi et al., 2025),若 A、B 兩組同比例增加,減幅比例不變,但絕對減碳量會略高於模型估計。

**推行困境**(可補進 1026 報告的困境頁):

> 共同配送會讓司機配送不熟悉的他牌門市;文獻指出固定司機服務固定區域有助於降低營運成本(Rashidi et al., 2025 第 2.1 節整理之一致性車輛路線問題文獻)。
